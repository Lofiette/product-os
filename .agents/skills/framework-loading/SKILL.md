# framework-loading

Use after task classification and product area selection.

## Procedure

1. Identify task type: product, UI/design, frontend implementation, API/data, risk, research, runtime, greenfield, redesign.
2. Select the smallest useful roles.
3. Select skills and gates needed for the next operation only.
4. Prefer role simulation by default.
5. Propose real subagents only when independent artifacts or parallel review are worth the cost.
6. Ask approval before real subagent spawn.
7. If framework paths are unknown, ask for bounded framework-index discovery.

## Output

Framework Loading Plan:

- roles to simulate;
- roles to spawn, if any;
- skills/playbooks/gates to load;
- why each is needed;
- skipped roles and rationale;
- approval request if needed.
