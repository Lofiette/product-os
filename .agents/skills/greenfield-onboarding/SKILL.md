# greenfield-onboarding

Use when the product or module does not exist yet.

## Principle

Greenfield Product Knowledge starts as planned/hypothesis knowledge and becomes confirmed only after design, implementation, or verification evidence exists.

## Evidence types

- user-approved decision;
- hypothesis;
- design artifact;
- implementation evidence;
- verification evidence;
- assumption;
- needs validation.

## Procedure

1. Capture user brief and product goal.
2. Create initial hypothesis `PRODUCT_MAP` or area map with low/medium confidence.
3. Record durable decisions as decision records.
4. Update maps as implementation artifacts are created.
5. Never mark planned behavior as confirmed until evidence exists.
6. Use Impact Map before first implementation.

## Output

- Hypothesis product map;
- decisions;
- unknowns;
- implementation evidence plan;
- review triggers.
