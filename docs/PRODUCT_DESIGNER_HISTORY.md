# Product Designer release history

Latest patch ID: `product-designer-4.1`
Base package: `codex-product-os 4.1.0`
Status: structurally integrated, deterministically validated, and offline-regression safe. Live model design quality and live optional-provider integration remain uncertified.

## Product OS 4.0 baseline

Product OS 4.0.0 is the complete pre-redesign baseline. Its Product Designer was disciplined at specification, state coverage, handoff, and routing, but it did not yet contain the new source-governed UI craft canon, Design Intelligence layer, Interaction Intelligence, dedicated form/professional-interface expertise, or portable execution plane.

## Product Designer 4.1 redesign

Product OS 4.1.0 is the first complete release of the redesigned Product Designer. Internal Preview 1 and Preview 2 builds were development checkpoints only. The release combines three planes without making the role dependent on one model, client, or plugin:

1. `UI Craft and Critique`: source-governed visual foundations, visual contract, adversarial self-critique, rendered evidence, and a 16-dimension review rubric.
2. `Interaction Intelligence`: behavioral lenses, interaction-pattern selection, form/task-flow design, and professional data-interface design.
3. `Design Execution Plane`: capability discovery, provider-neutral execution lanes, portable evidence contracts, and optional provider adapters.

The Product Designer owns the problem, pattern composition, UI decision, acceptance criteria, and final CPT gates. Execution tools may produce artifacts, but they do not own design judgment.

## Four native canonical skills

- `cpt-interaction-pattern-selection`
  - classifies page, task, navigation, workspace, command, and data-exploration needs;
  - uses 12 behavioral lenses and 44 reusable pattern cards;
  - requires alternatives, `use_when`, `avoid_when`, forces, states, accessibility, evidence, and falsification.
- `cpt-form-task-flow-design`
  - applies question reduction, flow-mode selection, semantic controls, validation timing, focus/error recovery, review/confirmation, upload, repeatable entry, and save/resume;
  - includes 8 workflow modes and 24 pattern cards.
- `cpt-professional-data-interface-design`
  - protects expert throughput, density, stable orientation, keyboard operation, bulk scope, permissions, linked data views, partial failure, and auditability;
  - includes 7 workflow profiles for tables, dashboards, editors, operations, analytics, multi-workspace, and hybrid field/desktop use.
- `cpt-design-execution-orchestration`
  - probes actual capabilities instead of assuming a provider;
  - selects the smallest audit, visual-direction, prototype, coded-candidate, QA, export, or preview lane;
  - produces a Design Execution Brief and Execution Evidence Packet;
  - requires fallback and independent acceptance.

These skills are recorded as native 4.1 additions in `SKILL_MIGRATION.json:new_skills`; the 95 legacy mappings remain intact.

## Optional OpenAI Product Design compatibility

The environment has no hard dependency on OpenAI Product Design.

When the plugin is actually discovered in the active Codex environment, the optional adapter can map exposed capabilities such as context playback, ideation, image-to-code, audit, and design QA into the provider-neutral execution contract. Discovery output is authoritative; the adapter must not invent hidden actions.

Provider output remains evidence, not a verdict. The CPT Product Designer still owns:

- problem and pattern decisions;
- source authority and design-system constraints;
- state, content, accessibility, and responsive completeness;
- acceptance criteria;
- `gate-design-quality`, `gate-product-value`, and `gate-accessibility`.

If the plugin is absent, the generic adapter and normal CPT role handoffs remain valid.

## Source transformation

The source books are not bundled. 4.1 contains only transformed operational knowledge:

- visual craft remains grounded in Malewicz and Malewicz;
- interaction structure and behavior lenses are derived from Tidwell, Brewer, and Valencia;
- form, validation, inclusive operation, and long-process knowledge are derived from Silver.

Dated screenshots, product examples, jQuery/browser workarounds, old ARIA recipes, and unsupported universal claims remain historical or quarantined. Current platform, accessibility, security, and technical implementation require project or current official authority.

## Product Designer workflow

The material workflow now covers:

1. Frame the real problem and evidence.
2. Play back context and expose material uncertainty.
3. Reconstruct domain, objects, actions, permissions, IA, and states.
4. Classify page, task, behavior, frequency, expertise, risk, and session model.
5. Select and compare interaction-pattern compositions.
6. Activate form/task-flow or professional-interface specialization when needed.
7. Define hierarchy, UI craft, content, and design-system contract.
8. Plan the smallest portable execution lane when an inspectable artifact is required.
9. Execute or hand off without surrendering design ownership.
10. Complete states, recovery, responsive behavior, and implementation contracts.
11. Run adversarial critique, rendered QA, and independent gates.
12. Define validation, falsification, residual risk, and stop condition.

## Evaluation expansion

The Design Intelligence suite now contains 20 cases. 4.1 adds coverage for:

- competing interaction-pattern families;
- question reduction before layout;
- focus and error recovery;
- multi-session and multi-actor processes;
- expert tables and bulk operations;
- linked analytic views;
- no-provider fallback;
- optional OpenAI adapter use without transfer of accountability.

## Honest boundary

The checks prove package consistency, routing, source-policy structure, trigger behavior, migration safety, deterministic regressions, and portable execution contracts. They do not prove that a live model will design at expert level, that every client exposes the same tools, or that OpenAI Product Design integration works until it is actually discovered and exercised in Codex. Rendered artifacts and calibrated human review remain required for final design-quality claims.
