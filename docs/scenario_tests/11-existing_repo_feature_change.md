# Scenario 11: existing_repo_feature_change

## Description
Implement or review a feature in an existing repository where stack and scripts must be discovered first

## Work mode
Production change / MVP / Bugfix

## Complexity
Fast Lane/Standard depending on scope

## Required roles
- `intake_orchestrator`

## Optional roles
- `team_architect`
- `frontend_architect`
- `backend_architect`
- `qa_engineer`
- `code_reviewer`
- `chronicle_keeper`

## Forbidden roles
- `market_researcher`
- `incident_investigator`

## Required skills
- `repo-recon`

## Limits
- Max active roles: 7
- Max questions: 7

## Expected gates
- Repo Recon before deep planning or edits
- Do not assume stack/scripts
- Use existing patterns before new abstractions
- Generated/forbidden zones identified
