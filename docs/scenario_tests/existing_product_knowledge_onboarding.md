# existing_product_knowledge_onboarding

## Purpose
Validate phased Product Knowledge onboarding for an existing repository.

## Expected behavior
- Phase 2 path-only shape scan before file content reads.
- Phase 3 app shell/top navigation before area maps.
- Create compact PRODUCT_MAP and KNOWLEDGE_INDEX.
- Create area maps only with approved evidence.
- Keep confidence, freshness, evidence, unknowns, and review triggers explicit.
- Do not create a giant PRODUCT_BRIEF.

## Must not
- Read root TASK/CHRONICLE as active memory.
- Read archives/generated files by default.
- Create deep flow maps before task-driven need.
