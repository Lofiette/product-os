# CPT Design & UI

Design and coded UI quality workflows.

## Skills

- `cpt-accessibility-review` — Use to review semantics, keyboard, focus, labels, ARIA, announcements, contrast, motion, and accessible error/recovery behavior.
- `cpt-content-design` — Use to design or review UX copy, terminology, messages, content realism, and localization readiness; not for brand campaigns.
- `cpt-conversation-design` — Use for chat, assistant, voice, or multi-turn flows including clarification, repair, confirmations, fallback, and human handoff.
- `cpt-data-visualization-review` — Use to design or review charts, dashboards, reports, metric semantics, scales, aggregation, comparison, and cognitive load.
- `cpt-design-handoff` — Use to produce and validate design-to-development handoff so implementation does not require guessing structure, states, components, content, or constraints.
- `cpt-design-recon` — Use to discover design-system mode, components, tokens, patterns, references, and UI constraints before design or coded UI work.
- `cpt-design-system-code-audit` — Use to run deterministic code-level checks for design-system imports, raw values, duplicate primitives, and contract deviations.
- `cpt-design-system-governance` — Use to establish design-source authority, component/token contracts, manifest lifecycle, compliance, and approved deviations.
- `cpt-interaction-state-model` — Use to define interaction behavior and complete state coverage across empty, loading, success, error, permission, responsive, and edge cases.
- `cpt-reference-taste-calibration` — Use to extract a reference/taste contract, good-bad examples, and design criteria before choosing or critiquing a direction.
- `cpt-screen-module-design` — Use to create or redesign a screen, flow, module, or prototype with hierarchy, states, components, content, and implementation handoff.
- `cpt-visual-acceptance-review` — Use to review rendered UI and coded interaction against specs, references, design system, states, taste, responsiveness, and obvious defects.
