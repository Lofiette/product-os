# CPT Design & UI

Design, interaction intelligence, forms, professional interfaces, portable execution, and coded UI quality workflows.

## Skills

- `cpt-accessibility-review` — Review semantics, keyboard, focus, labels, ARIA, announcements, contrast, motion, and accessible error/recovery behavior.
- `cpt-content-design` — Design or review UX copy, terminology, messages, content realism, and localization readiness.
- `cpt-conversation-design` — Design chat, assistant, voice, or multi-turn flows including clarification, repair, fallback, and handoff.
- `cpt-data-visualization-review` — Design or review charts, dashboards, reports, metric semantics, scales, aggregation, and comparison.
- `cpt-design-execution-orchestration` — Discover available capabilities and orchestrate audits, visual directions, prototypes, image-to-code, visual QA, export, and preview publishing with fallbacks.
- `cpt-design-handoff` — Produce and validate design-to-development handoff so implementation does not require guessing.
- `cpt-design-recon` — Discover design-system mode, components, tokens, patterns, references, and UI constraints.
- `cpt-design-system-code-audit` — Run deterministic checks for design-system imports, raw values, duplicate primitives, and deviations.
- `cpt-design-system-governance` — Establish design-source authority, component/token contracts, lifecycle, compliance, and deviations.
- `cpt-form-task-flow-design` — Design forms, validation, focus, search/filter/upload, repeated entry, save/resume, and long multi-actor processes.
- `cpt-interaction-pattern-selection` — Classify pages/workflows and select pattern compositions from behavior, IA, navigation, command, list, and data needs.
- `cpt-interaction-state-model` — Define behavior and complete state coverage across asynchronous, permission, responsive, and edge cases.
- `cpt-professional-data-interface-design` — Design dense tables, dashboards, bulk actions, linked data, keyboard speed, permissions, audit, and partial-failure recovery.
- `cpt-reference-taste-calibration` — Extract a reference/taste contract, examples, and criteria before choosing or critiquing direction.
- `cpt-screen-module-design` — Create or redesign a screen, flow, module, or prototype with reasoning, patterns, UI craft, states, portable execution, and handoff.
- `cpt-visual-acceptance-review` — Review rendered UI against product goals, specs, sources, design system, UI craft, states, responsiveness, and accessibility.

## Product Designer 4.1

The Product Designer selectively combines four layers:

1. Source-governed visual craft and critique derived for Product Designer 4.1.
2. Interaction pattern selection from transformed Tidwell material.
3. Form and inclusive-task design from transformed Silver material.
4. A vendor-neutral execution plane with an optional OpenAI Product Design adapter when visibly available in Codex.

The source books are not bundled. Derived knowledge stores problem, context, forces, procedure, alternatives, states, evidence, and failure conditions rather than copied prose or historical screenshots.
