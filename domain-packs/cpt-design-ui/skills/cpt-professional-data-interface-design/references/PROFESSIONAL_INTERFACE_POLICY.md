# Professional Interface Policy

Policy ID: `cpt-professional-interface-policy-v1`
Source basis: Tidwell et al., *Designing Interfaces*, with form and inclusive-interaction support from Adam Silver.

## Core position

Professional products optimize the whole human-system workflow, not screenshot neatness. Necessary complexity should become legible, stable, fast, reversible, and inspectable. Novice support must not permanently tax experts, and expert acceleration must not make the first successful action impossible.

## Design priorities

1. Correct decision and consequence.
2. Stable object, selection, permission, and state semantics.
3. Comparison, throughput, and error recovery.
4. Keyboard and assistive-technology parity.
5. Information density matched to task and display.
6. Traceability, audit, and repeatability where risk requires them.
7. Visual craft and polish that improve scanning rather than decorate it.

## Required distinctions

- information density vs visual noise;
- saved draft vs committed state;
- selected visible rows vs all matching records;
- routine action vs destructive or cross-scope action;
- no data vs not loaded vs permission denied vs stale;
- full success vs partial success vs queued work;
- personal history/shortcuts vs organizational audit log;
- exact values vs visual trends;
- novice guidance vs expert accelerator.
