# CPT Reference Taste Calibration

## Use when

- The user provides visual references, adjectives, examples, or an open-ended quality direction.
- Several design alternatives need disciplined critique.

## Do not use when

- The task has a fully governed spec and no subjective design decision remains.

## Required inputs

- References, good/bad examples, user adjectives, product/audience, design-system mode, constraints, and goal.

## Method

1. Separate what to learn from what must not be copied.
2. Extract layout, hierarchy, density, rhythm, typography, color/emphasis, component anatomy, interaction, content tone, and emotional qualities.
3. Translate examples into transferable principles and anti-patterns.
4. Classify must-match, may-adapt, and must-not-copy aspects.
5. Create taste dimensions and observable acceptance criteria.
6. Critique alternatives against user goal, system, evidence, maintainability, and taste rather than personal preference.
7. Get approval for material deviations before implementation.

## Output contract

Produce a compact artifact containing:

- `Reference/Taste Contract.`
- `Good/bad example board with derived rules.`
- `Critique matrix and selected direction.`
- `Approved deviations and unresolved interpretation.`

## Evidence standard

- A reference is a constraint or inspiration only as explicitly agreed.
- “Feels premium” must be translated into observable criteria.

## Stop and escalate

- References conflict and priority is unknown.
- Copying would violate IP/brand constraints.

## Failure modes to avoid

- Saying “looks similar” without a delta table.
- Copying surface styling while missing interaction hierarchy.
