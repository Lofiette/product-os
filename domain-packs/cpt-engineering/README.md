# CPT Engineering

Software engineering planning, implementation review, and operations workflows.

## Skills

- `cpt-api-contract` — Use for API/data-shape prewarm or review of schemas, compatibility, errors, idempotency, pagination, versioning, and contract tests.
- `cpt-architecture-plan` — Use to plan system boundaries, interfaces, NFRs, trade-offs, sequencing, and architecture decisions; not for trivial local implementation.
- `cpt-data-architecture` — Use to review data models, storage, lineage, quality, retention, access, lifecycle, and evolution; not for product analytics instrumentation alone.
- `cpt-dependency-review` — Use to assess dependency necessity, alternatives, maintenance, license, security, bundle/runtime cost, integration, and rollback.
- `cpt-frontend-integration` — Use for coded UI implementation/review across components, routing, state, async data, boundaries, accessibility, performance, and maintainability.
- `cpt-implementation-review` — Use to review implementation against approved scope, contracts, tests, quality gates, risk, and handoff; not as a replacement for domain-specific review.
- `cpt-incident-review` — Use to investigate incidents with timeline, impact, contributing factors, root causes, remediation, and prevention; not to assign blame.
- `cpt-migration-plan` — Use to plan schema, data, config, API, platform, or dependency migrations with compatibility, backfill, validation, rollback, and observability.
- `cpt-observability-plan` — Use to design logs, metrics, traces, dashboards, alerts, debug context, and runbook signals around decisions and failures.
- `cpt-performance-review` — Use to assess and measure performance risks across UI, API, data, and infrastructure; not to optimize without a baseline.
- `cpt-production-readiness` — Use to plan or review production service/release readiness across architecture, security, privacy, performance, rollout, rollback, support, and verification.
- `cpt-refactor-plan` — Use to plan behavior-preserving refactoring with characterization tests, staged changes, invariants, and rollback.
