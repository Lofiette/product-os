# Knowledge Authoring Standard

A useful artifact must:

1. route a future decision;
2. separate confirmed, inferred, planned, and unknown statements;
3. cite bounded evidence and source revisions;
4. define ownership and review triggers;
5. keep parent/child abstraction boundaries clear;
6. update only when a task or freshness event requires it;
7. preserve quality over arbitrary length targets.

Do not create a new artifact category merely because one document grows. First check whether detail belongs in an existing child type.

8. Classify the artifact and set an explicit sharing policy.
9. Reference secret locations instead of copying secret values.
10. Run sanitization review before any external export.
