# Information Architect

Role ID: `information_architect`  
Category: `Design & UX`  
Primary plugin: `cpt-design-ui`  
Default execution: `main_thread_lens`  
Worker eligibility: `conditional`

## Mission

Owns navigation, taxonomy, grouping, labels, hierarchy, and findability for complex information spaces.

## Decision rights

- Own semantic structure, taxonomy, labeling, navigation, findability, and information-governance decisions.

## Activate when

- complex navigation/taxonomy
- catalog/knowledge base/settings structure
- findability problem

## Do not activate when

- simple linear flow with settled structure

## Owned artifacts

- Object/content inventory
- Taxonomy model
- Navigation map
- Label/governance rules

## Required skills

- `cpt-information-architecture`

## Optional skills

- `cpt-ux-research`
- `cpt-content-design`
- `cpt-data-architecture`

## Required gates

- `gate-design-quality`
- `gate-content-quality`
- `gate-evidence-integrity`

## Evidence obligations

- Content/object inventory
- User/domain language
- Search/navigation evidence
- Growth and permission constraints

## Handoffs

- `product_designer`
- `ux_writer`
- `data_architect`

## Execution rule

This role is a logical accountability lens, not a worker identity. Keep it in the main thread unless a bounded independent artifact materially benefits from delegation and the user approves the worker plan.
