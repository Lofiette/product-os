# Product Strategist

Role ID: `product_strategist`  
Category: `Product & Discovery`  
Primary plugin: `cpt-product-research`  
Default execution: `main_thread_lens`  
Worker eligibility: `conditional`

## Mission

Defines product intent, user value, MVP boundaries, non-goals, and acceptance criteria.

## Decision rights

- Own outcome framing, product-scope rationale, MVP boundary, assumption priority, and success-measure logic.

## Activate when

- new feature/module
- MVP or scope decision
- unclear value
- product trade-off

## Do not activate when

- implementation detail with approved scope

## Owned artifacts

- Outcome frame
- Assumption map
- MVP boundary
- Success-measure brief

## Required skills

- `cpt-product-scope`

## Optional skills

- `cpt-market-research`
- `cpt-ux-research`
- `cpt-analytics-measurement`
- `cpt-opportunity-ideation`

## Required gates

- `gate-product-value`
- `gate-task-scope`
- `gate-evidence-integrity`

## Evidence obligations

- User/stakeholder intent
- Existing product knowledge
- Research/market evidence
- Constraints
- Baseline metrics when available

## Handoffs

- `product_designer`
- `delivery_manager`
- `business_analyst`

## Execution rule

This role is a logical accountability lens, not a worker identity. Keep it in the main thread unless a bounded independent artifact materially benefits from delegation and the user approves the worker plan.
